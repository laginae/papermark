# 扫描图书目录识别

[English](book-contents.md)

PaperMark 0.9 在原有论文标题识别之外，新增本地“图书目录页”流程。它读取书中已有的印刷目录，不会为没有目录的图书凭空生成章节。网页版、离线 HTML 和 Obsidian 插件均支持，保留中英文切换。

1. 添加 PDF，在“本地识别”中选择“图书目录页”。填写目录所在的实际 PDF 页码，例如 `2-4, 6`。不知道位置时，展开“不确定目录在哪几页？”，查找前 10、20 或 40 页。核对候选范围后点击“识别目录”。
2. 点击“自动校准页码”。程序结合印刷页码和正文标题，优先读取已有文字，扫描页使用当前选择的本地 OCR。Obsidian 桌面端支持已配置的 Paddle Small/Tiny；浏览器使用内置 Tesseract。此流程不上传 PDF、图片或识别文字。
3. 核对草稿：可修改标题、层级、印刷页码和目标 PDF 页码。点击“目录原页”和“跳转页”查看预览，核对后勾选“已核对”；不需要的条目取消“保留”。批量确认按钮表示你已核对所有建议跳转页，未定位条目仍需填写页码或排除。
4. 点击“应用已核对目录”，然后导出新 PDF。默认追加目录，保留当前书签，再次应用相同的完整目录不会重复追加。“替换当前全部书签”需要主动勾选；应用后可用书签编辑器的“撤销”恢复。原图像和批注保持不变。

## 页码校准与人工修正

- PDF 页码从文件第 1 张开始，包含封面和插页。印刷页码支持阿拉伯数字（`12`）、罗马数字前言（`iv`）和分章页码（`II-12`、`A-3`），分别校准。
- 支持单栏和双栏、分离的标题与页码框，以及简单的换行标题。结合编号与缩进推断层级，层级仍可编辑。自动分栏不正确时，可手动指定单栏或双栏。
- 自动校准先抽查最多 40 个 PDF 页面，再核查最多 40 个目标附近页面，并复用已有 OCR。它不会自动穷尽长书的每一页。可在修正选项中填写其他 PDF 范围（最多 40 页），供下一次校准识别。
- 页码偏移推断要求至少两个页面提供支持。不同区段可采用不同偏移；证据冲突、插页位置不确定等情况会留作未定位。超出已验证范围的推算会明确标注，所有条目均须核对。
- 手动修正示例：印刷第 `1` 页对应 PDF 第 `9` 页。添加此对应关系后，会校准同一编号类型中从该印刷页码起的未确认条目。遇到插页或缺页，再添加新的对应关系。已确认的行和逐条手工指定的目标页保持不变；取消确认可重新计算自动结果，直接修改 PDF 页码可覆盖该条目。
- 再次识别只重建当前草稿，不改变已应用的书签。草稿按文档保存在内存，切换文档和语言不会丢失；关闭或刷新会丢失。关闭前请应用目录并保存书签 JSON，或导出 PDF。

## 可搜索文字层与适用范围

只有实际完成 OCR 的页面会添加文字层。需要整本扫描书都能搜索、复制时，请展开“本地 OCR 选项”，选择“全部页面”并运行 OCR，再保持“导出可搜索 PDF”开启。该 OCR 操作保留原有或手工编辑过的书签。PaperMark 的页面预览是画布，请在导出的 PDF 阅读器中搜索和选择文字。

模糊扫描、艺术字体、复杂多栏、特殊编号、同类页码重复编号及目录缺少页码等情况可能需要人工修正。自动测试使用合成中英文扫描样本，不代表对所有图书的识别准确率。仍沿用每份 PDF 100 MB / 2,000 页、最多 1,000 个书签的限制；长篇扫描书占用内存较多。取消任务会保留已完成页面的 OCR，但不应用半成品目录。

## 参考项目

本功能为独立 JavaScript 实现，参考了 MIT 许可的 [TOC Forge](https://github.com/electroniccc/toc_forge) 中的 `parsing.py`、`page_map.py`，以及 [pdf-toc-ocr](https://github.com/ennheng/pdf-toc-ocr) 的 `app/core.py`。主要借鉴按位置重组目录行、编号与缩进推断层级、区分页码类型和使用偏移证据的思路。PaperMark 不依赖这两个 Python 程序，也不调用它们的可选在线模型。
